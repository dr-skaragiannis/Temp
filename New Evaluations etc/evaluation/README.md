# MeshCrowd reproducible evaluation package

This directory contains data contracts, deterministic model-based experiments, detailed outputs, and Android integration code for retaining and downloading APK evaluation data as JSON.

## Important provenance note

The repository supplied to this task contains the React research website, not the original Android/Gradle application and not the original phone radio captures. Consequently:

1. The JavaScript harness reproduces the **published model configuration** and runs 4,161 deterministic scenes through production-compatible signal-processing steps.
2. It does not claim to recreate missing field captures.
3. The Kotlin recorder/exporter is ready to integrate into the real Android app, but it cannot be compiled into an APK until the Android source module is supplied.

These limits are recorded in every generated summary instead of being hidden.

```text
│   └── session.schema.json         # JSON Schema 2020-12
├── src/

│   ├── stats.mjs                   # median, variance, rates, grouping
│   ├── model.mjs                   # RF model, DSP, ranging, epochs, mesh
│   └── suites.mjs                  # fusion/ranging/epoch/transit/mesh suites
├── outputs/latest/                 # generated by run.mjs
└── android/                        # APK recorder + JSON export integration
```

## Requirements

- Node.js 20 or later.
- No npm packages are required by the evaluation runner.

## Replicate the experiments

From the project root:

```sh
node evaluation/validate.mjs
node evaluation/tests/self-test.mjs
node evaluation/run.mjs
node evaluation/inspect.mjs
```

The suite counts sum exactly to 4,161:

| Suite | Scenes | Purpose |
|---|---:|---|
| Fusion | 1,512 | Multi-band detection and pedestrian/vehicle typing |
| Ranging | 288 | dBm inversion, quality gate, and noise-floor refusal |
| Epoch | 864 | 10 s stable-level change detection versus last-sample comparison |
| Transit | 768 | Two-node RFCOMM/L2CAP counting by separation |
| Mesh | 729 | Multi-node confirmation, Byzantine outliers, and reliability reward |
| **Total** | **4,161** | — |

### Detailed raw arrays

The default output keeps event features and every scene outcome but omits generated sample arrays to remain small. Include every RSSI sample with:

```sh
node evaluation/run.mjs --include-samples --out=outputs/with-samples
```

### Determinism check

Run twice to different folders and compare the printed hashes:

```sh
node evaluation/run.mjs --out=outputs/run-a
node evaluation/run.mjs --out=outputs/run-b
```

The `reproducibilityHash` values must match for the same config, code, and seed.

## Getting details

- Read `outputs/latest/summary.json` for headline and per-suite metrics.
- Read `outputs/latest/suite-details.json` for per-band, per-radius, per-distance, and per-separation matrices.
- Stream/filter `outputs/latest/scene-results.jsonl` for individual scene features and decisions.
- Compare generated metrics with `data/reference-targets.json`. Targets are comparison data; the runner does not hard-code them as results.
- See `DATA_DICTIONARY.md` for every APK and output field.

## APK JSON retention and download

Copy `android/src/main/java/org/meshcrowd/evaluation/` into the actual Android app module and follow `android/README.md`.

The integration:

- writes each run to `filesDir/evaluation/session-*.json`;
- atomically checkpoints every 100 records and when the app backgrounds;
- hashes SSIDs/BSSIDs/BLE addresses with a per-session salt;
- exports one or all sessions with Android's `ACTION_CREATE_DOCUMENT` picker;
- uses MIME type `application/json` and requires no broad storage permission.

The exported file conforms to `schemas/session.schema.json` and can be archived alongside the model outputs.

## Reproducibility principles

1. Every constant lives in `config/experiment.config.json`.
2. The random seed is fixed and included in every summary.
3. Scene-level decisions are retained, not only aggregate percentages.
4. The SHA-256 reproducibility hash covers all ordered scene results.
5. Published targets are not used to overwrite generated results.
6. Missing original field data is stated explicitly.

Cost and usability measurement: `meter/` (battery, background operation, storage, traffic,
usability protocol, analysers). Start with `meter/README.md`; repo-specific wiring is in
`meter/INTEGRATION.md`. Nothing in that directory is a measurement of the field campaign until
`meter/runs/` contains captures you took.
